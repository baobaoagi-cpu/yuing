## 交付順序

### 0. 通話先跑通（明早交付前的硬門檻）

1. 核對預覽服務部署 `SUCCESS`，且登入後取得的 `/api/yuling/token` 回傳 `agent=duanni-minimax-poc`。
2. 從手機按「撥打」，確認房間連線及 worker 出現該房間的 job/participant；說短句，逐段確認 STT 文字、M3 回應、TTS 音訊與手機實際聽到的內容。
3. 在 390 px Android 與至少一台 iPhone Safari/PWA 檢查麥克風授權、掛斷後重撥、背景切換回前台、登入保持與右下角影片不遮文字。
4. 若任何一段失敗，保留供應商、錯誤碼、時間點、房間匿名 ID；只把成功的階段標綠。未驗證的 STT/LLM/TTS 仍標未知。

這次合成測試暴露的首要品質問題是 Deepgram `nova-3`（`language=multi`）對中文句子的誤辨。下一輪先在真人手機錄音上比對轉寫，量測字錯率與最終回應；若仍偏差，再試明確中文語言參數或替代 STT。不得只因轉寫事件有回傳就宣稱「聽懂」。

### 1. B 版同一會話（明早最小可體驗）

一個聊天列表與輸入列承載文字、圖片、網址；撥打進入沉浸通話，返回仍看到同一段對話。每則訊息有類型、時間、來源與傳送/失敗狀態。通話文字稿能進會話紀錄才算「雙向互動接合」；不能用前端假訊息冒充服務端回覆。生活聲結果作為候選事件顯示，須有信心值與可撤銷標記。

### 2. 可修正的記憶與知識（在通話後接）

先以隔離測試帳號建立 append-only 事件紀錄、明確的「記住／忘記」操作、來源與更新理由。向量索引只做檢索加速，不當事實原本；知識文件保留版本與來源。人物、地點、事件和因果只寫入經可追溯來源支持的關係，推論與事實分欄；先以簡單關係表/索引驗證，不為了名稱直接上圖資料庫。不得把私人本地 HOME 記憶複製進公開倉庫或共用 Railway 服務。

### 3. Hermes 技能養成（明早後續迭代）

端倪可自行探索候選技能與公開資料，形成「需求 → 候選 SKILL/MCP/API → 沙盒測試 → 區域型流暢性監督 → 權限/成本確認 → 啟用 → 回退」紀錄。明早版本只允許白名單讀取和提案，不讓對話內容直接觸發任意套件安裝、shell、憑證使用或付費。每個候選附開源授權、下載來源、上海可達性與延遲證據；現有 LiveKit、前端 SDK、本機 POC 已足夠支撐通話驗證，暫無需要現在下載的新開源套件。

## 上海區域型流暢性監督

用上海朋友自己的 Android/iPhone 各做至少 3 通、每通 3–5 分鐘，記錄：頁面首次可互動時間、麥克風授權成功率、點撥打到入房、語音結束到首個回話音、完整回話時間、斷線/重連、圖片/網址上傳延遲及失敗原因。逐個列 LiveKit、Deepgram、MiniMax 國際端點、Railway；Railway 新加坡部署成功只證明新加坡容器在線，不代表中國網路流暢。以實測 p50/p95 和失敗率決定是否替換供應商或節點。

## 付費與停止線

- 現有 MiniMax 國際帳戶已購入點數，M3/TTS 試調用可用；專屬 Voice Design 仍須付費產生且需真人聽審，未獲確認前不執行。
- LiveKit、Deepgram 的現有使用可能依流量計費；不要新購人民幣 API 或新增付費資料庫來換取「看似完整」的架構。
- Chrome 密碼管理工具將測試帳號現用弱密碼標成已外洩。給上海朋友前應改成獨立強密碼、撤換共用測試憑證；本次沒有將它儲存於瀏覽器密碼管理工具。
- 給上海朋友之前，至少通過實際通話、登入隔離、資料不串號、可刪除測試記憶及中國區連線測試。若未通過，只發內部測試網址並標明不能正式體驗。

## 已發現的獨立缺陷

`backend/routes.py` 的 `/api/yuling/calls/<call_id>/event` 以四個位置參數呼叫 `record_audio_event`，`backend/storage.py` 卻只接受兩個位置參數與 keyword；舊 Railway 日誌曾回 500。這會影響生活聲事件記錄，須修正後用端點測試及重新部署驗證。通話即時鏈路與此缺陷分開驗收。
